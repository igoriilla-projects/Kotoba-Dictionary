# Локальные данные словаря

В Git хранятся этот файл и `manifest.json` с версией схемы, числом записей и
хэшами исходных файлов для экспорта из образа. Содержимое словаря хранится
локально и защищено отдельными правами.

Для сборки используйте собственный исходный образ `YARXI.dmg`:

1. Поместите его в корень проекта под именем `YARXI.dmg`.
2. Загрузите `JMdict_e.gz` в каталог `Data/`. Подходит и архив `JMdict_e_NG.gz`, сохранённый под именем `JMdict_e.gz`. [Архив EDRDG](https://www.edrdg.org/pub/Nihongo/)
3. Из корня проекта выполните:

   ```sh
   python3 tools/extract_database.py YARXI.dmg
   ```

Конвертер без монтирования и запуска исходного приложения создаст:

- `Data/yarxice.db` — неизменную исходную бинарную базу;
- `Data/dictionary.sqlite` — базу SQLite для приложения и виджета;
- `Data/manifest.json` — манифест экспорта.

Образ, справочник JMdict, базы и временные файлы исключены через `.gitignore`. Не добавляйте их принудительно в Git. Исходные файлы сохраняйте для повторного экспорта и проверок. Манифест содержит хэши исходных файлов, хэш архива JMdict, версию обработки чтений и итоги сверки слов.

Сборка пересоздаёт базовый экспорт, если версия обработки чтений устарела. Для
сборки с готовым экспортом актуальной версии исходный образ и справочник нужны
только при повторной конвертации. Запуск приложения и виджетов работает офлайн.
Чтобы обновить справочник, скачайте свежий архив и повторите экспорт. Параметр
`--jmdict` позволяет явно указать путь к архиву.

После подготовки данных:

```sh
xcodegen generate
bash tools/build.sh
bash tools/test.sh
```

При переносе уже настроенного проекта можно локально скопировать исходный образ и обе базы. Данные обучения пользователя в этот каталог переносить не нужно: они хранятся отдельно в App Group и не входят в Git.

При наличии `Data/yarxi.db` скрипты сборки macOS и Linux создают расширенный
экспорт во временном каталоге и включают его в пакеты. В macOS один и тот же файл
поставляется с приложением и виджетом. Если свежей базы нет, используется экспорт
из образа. Конвертация распространяет прежние идентификаторы на однозначные
совпадения и оставляет старые карточки при неоднозначных совпадениях.

## Windows 10 / 11

На Windows сначала подготовьте `Data/dictionary.sqlite` командой
`python tools/extract_database.py YARXI.dmg`. Если в `Data/` есть свежая SQLite-база
`yarxi.db`, скрипт сборки преобразует её в локальный `Data/dictionary.windows.sqlite`
и включит результат в приложение под именем `Data/dictionary.sqlite`. Конвертер
сохраняет идентификаторы карточек по однозначным совпадениям, а для остальных
сохраняет прежние карточки. Заново выполнить только конвертацию можно командой
`python tools/extract_database.py --sqlite-source Data/yarxi.db`. Для этой
конвертации тоже нужен локальный архив JMdict.

Запустите `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_windows.ps1`.
Приложение читает словарь из своего пакета. При отсутствии `Data/yarxi.db`
сборка использует экспорт из образа. Хэш свежего источника и число записей
хранятся в таблице `metadata` отдельного Windows-экспорта.
Учебные данные Windows хранятся отдельно в `%LOCALAPPDATA%\Kotoba`; переносить их
в `Data/` или добавлять в Git не нужно. Полная инструкция — [Windows](../docs/WINDOWS.md).
